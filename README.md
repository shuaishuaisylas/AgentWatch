# AgentWatch

本机运行的 Codex / Claude Code / WorkBuddy / Cursor 会话看板。Cursor 提供可观测状态事件；订阅额度可独立保存官网页面读数，token 仍保持未知。数据只留在这台 Mac，提供 Web 看板和桌面胶囊。

## 拉取后开始

面向 macOS，需有 Python 3.9 及以上。无需安装 Python 第三方依赖，也没有 npm 安装或前端构建步骤。

```sh
git clone --branch codex/desktop-capsule https://github.com/shuaishuaisylas/AgentWatch.git
cd AgentWatch
python3 -m agentwatch --demo --port 8767 --open
```

这是供前端开发使用的**演示模式**：展示人工样例，不采集真实会话，不修改真实 Agent 配置，不打开真实应用。数据和来源目录全部临时创建，别名只保留在本次运行中；退出服务后清理。页面应明确标识演示数据，不能把样例当作本机实测结果。

前端与后端由同一个 Python 服务提供。不要直接双击 `web/index.html`，也不要另起静态服务器或 Vite 来连接本地 API；页面需要同源 cookie 和 CSRF 校验。修改 `web/` 后刷新页面即可。Node.js 仅用于可选的 JavaScript 语法检查，不是运行依赖。

协作前按顺序阅读 [AGENTS.md](AGENTS.md)、[交接说明](docs/HANDOFF.md)、[API 约定](docs/API.md)。[协作指南](docs/CONTRIBUTING.md) 提供拉取当前功能分支、创建个人分支、验收和可直接交给开发 Agent 的开工指令。后端主要在 `agentwatch/`，Web 前端在 `web/`，macOS 胶囊在 `desktop/`。默认分支在 PR 合并前不包含当前功能，接手时先核对分支。

## 使用真实本机数据

双击项目目录里的 **启动看板.command**，浏览器会打开 `http://127.0.0.1:8766`。服务运行在弹出的终端中；关闭服务时按 `Control + C`。

也可以在仓库根目录运行：

```sh
python3 -m agentwatch --open
```

看板读取的是运行者这台 Mac 的记录，无需共享账号、API Key 或原始会话。未安装相应工具或没有本地记录时仍可启动，只会显示空态；这不等于接入故障。端口被占用时，可以指定 `--port 8768`。第二次启动前先检查原服务是否还在运行。

## 桌面胶囊

macOS 原生客户端位于 `desktop/`，复用同一本机 API，不依赖浏览器常驻。需要带 Swift 的 Command Line Tools / Xcode；仓库只提供源码，不包含构建产物。先退出已有胶囊，再运行：

```sh
# 人工演示：构建并启动隔离服务，不连接真实来源
./desktop/scripts/run-demo.sh
```

真实模式先启动看板服务，再双击 `启动胶囊.command`。仅大于零的“执行”和“待处理”会显示；都没有时自动隐去，有新活动后重新出现，手动暂隐仍优先。详情支持可靠完成的已读确认与人工提醒的本地消除；不替用户回复或批准。更多操作及安全重启见 [桌面说明](desktop/README.md)，当前实现与验收边界见 [桌面交接](docs/DESKTOP_CAPSULE_CURRENT_HANDOFF.md)。

## 第一版能做什么

- 自动读取可发现的 Codex 本地会话索引、记录，以及 Claude Code、WorkBuddy 记录。保留原来的启动方式。
- 总览只展示今天有活动或当前在线的明确主会话。点击卡片查看明确关联的子 Agent 列表和状态；未知角色不归为主会话，也不自动挂到其他会话。
- 显示进程在线、来源报告的状态、最近阶段、上下文快照与已采集用量。子 Agent 的待处理提示保留在主卡片上；进程在线和执行中仍是不同指标。
- 历史统计改为北京时间当前自然年的每日 token 热力图，工具筛选默认“合计”。没有记录的日期显示未知，已报告的零值保留为 0，未来日期单独标注。年度合计包含所有角色，缓存和推理分项不重复相加；不因主卡片只显示主会话而丢失子 Agent 用量。旧日/周/月/年统计 API 保留兼容。
- 今日状态动态自动过期；长期保存会话元数据和数字统计。配置增强产生的临时事件文件在被采集后清空。
- 可在详情中给会话设置名称。读取 Claude 的显式自定义名称；不使用提示词或生成摘要作为标题。
- Cursor 需用户启用状态 hooks 后发现会话；首版只提供可观测状态，不读取其聊天数据库或推算用量，具体范围见下文。

## Codex / WorkBuddy 状态上报

在 **接入设置 → 对应平台 → 预览状态接入** 中启用生命周期 hooks，区分执行中、等待批准、等待回复、空闲和运行结束。首次启动只说明已接入，不推测已经空闲；一次工具失败也不等于整个 Agent 已失败。状态事件优先于原始记录，主子会话分开处理，已结束轮次的迟到工具事件不会重新激活会话。

配置分别合并到 Codex 用户目录的 `hooks.json`、WorkBuddy 用户目录的 `settings.json`，保留原有设置和其他 hooks，保存前备份并检查文件是否变化。新增命令只上报允许的元数据，静默退出，不返回批准、拒绝、上下文或任务指令。撤销只移除 AgentWatch 添加的项，保留后续其他修改。短时同步执行上报（最多 3 秒），避免异步事件乱序；临时事件文件被采集后清空。

**Codex 还需要在客户端亲自审阅信任。** 在 Codex CLI 输入 `/hooks`，查看新增 AgentWatch 命令并信任；未信任的配置不会运行。修改配置后可能需要重新审阅。看板不会写入客户端信任记录或调整批准策略。信任后开启或继续会话，检查“最近状态上报”。桌面应用、CLI、编辑器是否实际加载配置，须分别以收到事件为准，不能由 CLI 成功推断所有入口都已生效。

WorkBuddy 启用后新开会话，发送普通问题并检查实际状态切换。配置已保存、客户端已信任、看板已收到上报，是三个不同事实。等待批准和等待回复必须有对应事件才展示，无法确认时保留待确认。

WorkBuddy 的桌面安全沙箱审批可能不触发 `PermissionRequest` hook。看板还会自动只读 `logs/<日期>/sdk/conversations/*.log` 中格式明确的状态机转换，补充沙箱审批、允许后继续执行和本轮空闲；其余诊断正文直接跳过，不进入数据库、游标或页面。提问工具的确认卡片按等待回复处理，不能仅因按钮写着“批准”就当作系统权限审批。该通道已在 WorkBuddy 5.8.2 实测；未来版本未识别的格式保持忽略，不能推测状态。

依据：[Codex 官方 hooks 与信任要求](https://learn.chatgpt.com/docs/hooks)、[WorkBuddy 插件与 hooks](https://www.codebuddy.cn/docs/workbuddy/Plugins)、[CodeBuddy hooks](https://www.codebuddy.cn/docs/cli/hooks)。

## Cursor 状态接入

在 **接入设置 → Cursor → 预览状态接入** 查看将新增的 hooks，确认后保存。配置合并到 Cursor 用户目录的 `hooks.json`，默认目录为 `~/.cursor`，自定义位置可通过 `--cursor-home` 指定。保存前备份并校验文件是否变化；撤销只移除 AgentWatch 添加的项。启用后新开或继续 Cursor Agent 会话，查看“最近状态上报”和实际状态变化。设置已保存不等于客户端已加载或真实事件已触发；演示模式禁止修改真实配置和打开真实应用。

首版只采集身份、时间、工作目录及明确事件等最少状态元数据，不保存提示词、思考正文、工具参数或结果。`beforeSubmitPrompt` 只表示请求已提交，仍待确认执行；`postToolUse`、`afterAgentThought`、`preCompact` 等明确执行事件可用于确认执行中。只有 `stop` 明确报告 `completed` 才记录本轮结束，不能据此宣称业务目标成功；事件陈旧后仍按统一规则降为待确认。

**等待回复、系统审批、子 Agent、token 和上下文尚未接入。** 当前会话标记为 `status_only`，缺失数字显示“—”，不会把事件次数换算成用量。人工待处理覆盖保持未知；待处理计数不证明 Cursor 当前无人需要处理，本轮结束也不会据此自动生成完成收件箱提醒。打开按钮仅打开 Cursor 应用，不保证定位原会话，也不会自动标记该会话已看过。

订阅额度可从已登录的 [Cursor 官方 Spending 页面](https://cursor.com/dashboard/spending) 读取并显式保存为本机页面快照。它与状态 hooks、会话 token 独立，不读取私有登录凭据，也不是个人余额自动查询 API。只保存服务端允许的额度池、百分比、周期、日期和读取时间；不保存账号或页面正文。官网整数百分比标为“约”，官方更新时间未知时保持 null，另显示页面读取时间。月度池、周池和 Grok Bot 分开，不能相加；不从美元消耗反算余额。超过 15 分钟标旧快照，进入可能重置日期后保守显示未知，不自动补满。看板“更新额度”不会自动重新读取 Cursor 网站，请通过“官网核对额度”检查后重新读取；接口见 `docs/API.md`。

该实现提供首版可观测状态覆盖，仍须在用户实际使用的 Cursor 版本与入口分别验收；配置合并测试和人工演示不能代替真实客户端验证。

## Claude Code 增强

记录默认可读，但记录本身不能保证准确识别“正在等你”。在 **接入设置 → Claude Code 准确状态** 中，可以预览并启用后台事件上报。

看板会给 Claude 用户 `settings.json` 增加异步 command hooks，保留原来的 hooks 和其他设置。启用前保存原文件备份，撤销时只移除看板添加的配置，并保留之后的其他修改。设置在预览后发生变化时，会要求重新预览。

终端上下文上报单独勾选。若已有状态栏，会保留其输入和标准输出；若无状态栏，添加一条简短显示。原状态栏命令的 stderr 不展示，最长等待 5 秒。

新增配置需要由新启动的 Claude Code 会话实际验证：设置保存成功不等于每个客户端都已经上报。“最近状态上报”时间可用于检查。尚未重启的会话、不同桌面引擎、被策略或插件覆盖的配置可能还不能提供准确状态。

## WorkBuddy 本地接入

自动只读 `~/.workbuddy/projects` 下的本机会话记录与上述 SDK 状态日志，提取会话身份、工作目录、明确状态和数字用量；不读取生成的对话标题或正文作为会话名称。默认读取不修改 WorkBuddy 设置；启用上面的状态增强时才合并 hooks。可通过 `--workbuddy-home` 或 `WORKBUDDY_HOME` 指定来源目录。

已采集的输入、输出和缓存 token 纳入年度热力图；旧统计接口保留日、周、月、年口径。记录未报告可靠主子关系时，不出现在主会话卡片或其他主会话的子列表中，并提示覆盖缺口。没有可靠运行事件时保留“待确认”；请求 token 不作为上下文占用，缺少有效快照时显示不可用。

本地会话、token 与生命周期事件不需要云端授权。积分余额通过独立的官方授权接口读取，配置方式见下文。跳转仅打开 WorkBuddy 应用，不能保证定位原会话。

## 订阅与积分剩余

首页新增账号额度卡片，独立于工具、项目、角色筛选和会话 token 统计。百分比保留来源精度；缺失数据不补零。快照超过 15 分钟显示“旧快照”，到达重置时间后剩余量显示“—”，直到来源重新报告。

| 平台 | 读取方式 | 条件与边界 |
| --- | --- | --- |
| Codex | 本地 `token_count.rate_limits` 快照 | 按实际 `window_minutes` 区分周额度、5 小时等窗口；不把 primary 固定当作 5 小时。不额外启动 Agent 或调用模型 API |
| Claude Code | 官方 statusLine 的 `rate_limits` | 在接入设置勾选“同时上报终端上下文和订阅额度”，预览并启用，然后由新的 Pro/Max 会话完成一次回复；5 小时与每周窗口可分别缺失 |
| WorkBuddy | 官方 `GET /openapi/v2/credit` | 需要具有 `user.credit.readable` 的官方 OAuth access token；返回资源包总额和已用积分，无法拆分订阅、充值、赠送，也不返回周重置时间 |
| Cursor | 官网页面快照（显式读取） | 个人自动额度 API 尚未接入；按池显示页面读数、读取时间与旧值提示，缺失时保持未知 |

WorkBuddy 读取运行环境中的 `AGENTWATCH_WORKBUDDY_ACCESS_TOKEN`。凭证由官方第三方应用授权流程获取，不复用或提取桌面软件的私有凭据。当前未实现应用注册/OAuth 登录界面或自动续期。未配置、授权失败或响应字段缺失时明确显示未知；不从本地累计 token 推算积分。

已具备正式授权凭证时，可在 macOS zsh 终端隐藏输入后启动（令牌不进入命令参数）：

```sh
read -s 'AGENTWATCH_WORKBUDDY_ACCESS_TOKEN?WorkBuddy access token: '
export AGENTWATCH_WORKBUDDY_ACCESS_TOKEN
python3 -m agentwatch --open
```

积分服务每 5 分钟后台查询一次；“更新额度”可请求更新，最短间隔 30 秒。凭证仅保留在本次进程内存，不进入数据库或页面；余额以内存快照返回看板，不写入数据库。演示模式完全忽略凭证、不发网络请求，展示三家的人工额度样例。

Codex、Claude 的数字代表最近本机会话报告的账号额度；多账号切换或未启动客户端时可能不是当前登录账号的实时值，需结合来源时间和原客户端确认。当前账号的 Claude 状态栏上报与 WorkBuddy 正式授权仍需真实客户端验收。

依据：[Codex 官方额度字段](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)、[Claude 状态栏字段](https://code.claude.com/docs/en/statusline)、[WorkBuddy 积分接口](https://open.workbuddy.cn/en/docs/openapi)。

## 数字与状态的边界

- **在线**：匹配到 Agent 进程和会话记录/已上报的进程身份。并不代表正在执行。进程已退出也不表示业务任务成功。
- **执行中**：来源明确且未陈旧的 hooks / 状态事件可确认正在工作，即使暂时无法绑定进程；明确离线不计入执行中。原始记录仍需进程在线才能计入。超过 120 秒没有新执行事件时保守标为待确认；长期工具调用可能因此变成待确认。较旧的等待事件会显示“旧事件”，需跳回工具确认。
- **空闲 / 运行结束**：`Stop` 表示本轮回复已结束、当前空闲，`SessionEnd` 表示本次运行结束；均不等于业务目标已成功。进程在线可以同时处于空闲状态。
- **Codex**：本地记录提供用量、上下文和阶段；准确生命周期状态需要客户端信任并实际触发 hooks。看板不会新启动另一个 app-server 假装已附着到原客户端。
- **上下文**：显示来源最近报告的快照，不是实时精确测量。Claude 记录通常只有最近请求输入量；没有分母时不计算百分比。压缩后清空旧值，直到新的有效快照出现。
- **token**：Codex 输入已含缓存，输出已含推理；Claude 输入合并 fresh、cache read、cache creation；WorkBuddy 输入已含缓存，缓存别名只作为分项。分项不重复相加。同一个 Claude 请求的多条流式记录取已报告最大值。
- **历史缺口**：Codex 累计基线缺失时，只把可识别的最近请求用量记入对应日期，不把整段历史用量塞进当天。会话报告累计可能高于看板已采集累计。缺失字段显示 `—`。
- **任务**：Codex 的 `task_started` 是活动轮次，不能当作业务任务。Claude TaskCreated/Completed 有真实 ID 时才统计。没有可靠任务 ID 的工作不推测成任务数。

## 跳转

| 来源 | 当前行为 |
| --- | --- |
| Codex 桌面 | 使用 `codex://threads/<id>` 指定会话 |
| Codex VS Code | 使用已安装扩展的本地会话路由；详情提供 Codex 桌面备用入口。原 VS Code 窗口定位需客户端实际支持 |
| Claude 本机终端 | 进程在线且有 TTY 时，选中 Terminal.app 对应标签页。首次可能由 macOS 请求“自动化”权限 |
| Claude VS Code | 打开所属项目。暂不调用可能在会话不存在时新建对话的会话链接 |
| Claude 桌面 Code | 打开 Claude 应用；不保证定位到原会话 |
| WorkBuddy 桌面 | 打开 WorkBuddy 应用；不保证定位到原会话 |
| Cursor | 打开 Cursor 应用；不保证定位到原会话，不自动确认已看过 |

跳转只在用户点击时执行，不向 Agent 提交消息、批准任务或启动新的编程任务。未识别入口时按钮不可用。

Codex 需要已采集且仍存在的本地会话文件才启用跳转；只有状态上报的 ID 会显示原因，避免打开后找不到记录。Codex 内部记忆目录里没有索引或会话记录的临时状态项不作为新项目会话展示；正常用户会话和其他同名目录不受影响。

## 数据与安全

默认数据目录：`~/.local/share/agentwatch`。可用 `--data-dir` 修改。

采集来源默认是 `~/.codex`、`~/.claude`、`~/.workbuddy`、Cursor 的 `~/.cursor` hooks 目录和 Claude 本地 Code 数据目录；可通过 `--codex-home`、`--claude-home`、`--workbuddy-home`、`--cursor-home`、`--desktop-home` 指定，也支持 `CODEX_HOME`、`CLAUDE_CONFIG_DIR` 和 `WORKBUDDY_HOME`。不采集豆包工作、Claude Cowork、普通 Chat 和 DeepSeek Harness。

解析时仅提取会话标识、项目/工作目录、版本、主子关系、状态和数字用量。提示词、回复、代码、工具参数、工具结果和凭据不进入看板数据库、界面或日志。来源记录与数据库保持只读；用户启用状态增强时才修改对应 hook 配置。为了定位项目、匹配进程及跳转，数据库会保留本机路径、进程 ID / 启动身份和 TTY。

可回滚的原 Agent 设置备份可能包含原有环境变量和命令；它保存在私有权限目录中，不会发送到页面或统计数据库。目录权限为 `0700`，数据库和看板产生的文件为 `0600`。服务只监听 `127.0.0.1`，检查 Host/Origin，并使用浏览器 cookie 和操作校验令牌保护本地接口；不上传云端、不调用模型 API。
