## 第一次启动

准备 Python 3.9 及以上，在终端检查 `python3 --version`。前端无需 npm；如需运行 JavaScript 语法检查，再准备 Node.js。

```sh
git clone https://github.com/shuaishuaisylas/AgentWatch.git
cd AgentWatch
python3 -m agentwatch --demo --port 8767 --open
```

浏览器访问 `http://127.0.0.1:8767`。页面由 Python 后端提供，接口、cookie 与 CSRF 均在同一来源。保留服务终端；按 `Control + C` 停止。端口占用时换一个未占用端口。

演示数据全部人工生成，时间随样例刷新移动并保留相对陈旧程度。它只用于开发和界面验收，不能证明真实客户端接入成功。演示不运行采集或进程探测，来源和数据库使用临时目录；退出后清理，修改的会话别名不会保存到下一次运行。后端拒绝演示中的应用跳转及所有平台接入配置操作。

没有真实会话也可以开发总览、统计和设置页面及常见状态；其他边界场景按需补人工样例。需要检查真实采集时，在仓库根目录使用 `python3 -m agentwatch --open`，这会读取运行者自己的记录。不要为前端开发共享真实记录或开启真实状态增强。

## 接口变更如何配合

## 已知边界

实时列表会排除 Codex 已归档会话、归档父会话的后代及内部审核 Agent；正常子 Agent 继续展示。共享进程在线不能覆盖隐藏规则。归档与恢复会在重新发现来源后生效；历史用量和别名保留，历史项目仍可筛选。已有本地数据库会自动补充可见性字段，无需清空重采；具体优先级见 API 文档。

Codex 数据目录内 `memories` 的未知角色临时状态记录，在没有线程索引登记或已解析会话文件时也会隐藏。其他同名项目及正常持久会话保留；记录随后到达可恢复展示。仅有 hook 的普通会话显示“仅状态上报”，不能从 ID 生成可恢复承诺。Codex 跳转须有仍存在的已采集非空记录；API 与原应用打开前均检查，显式备用入口不能绕过。详情使用兼容新增的 `working_directory` 展示项目根目录或工作树路径，避免把非工作树项目误显示成目录未知。前端须兼容可选 `jump.reason` 和 `coverage=status_only`。

Codex 与 WorkBuddy 的接入预览、启用、撤销已接入设置页，接口为 `/api/{codex|workbuddy}/{preview|enable|restore}`；Claude 保留原接口。`lifecycles` 是 integrations 的兼容新增字段，前端应容忍旧后端缺少该字段。配置齐全、客户端信任、已收到事件分别展示；`review_required` 仅表示平台要求审阅，不能作为实际信任结果。

已与用户配合核验 Codex CLI 和 WorkBuddy 5.8.2 的执行 → 系统等待批准 → 用户允许后继续执行 → 空闲；在用户保留真实批准框时，看板对应卡片确实显示等待批准。WorkBuddy 通过临时 `pwd` 询问规则触发真实沙箱拦截，验证后已删除该规则，保留原默认策略。另收到 Codex 桌面的执行与提问事件，以及 Claude 开始执行、接入和运行结束事件。Claude 的批准链路、等待回复的完整交互和各桌面/编辑器入口尚未全部实测；不能从一个入口的结果推断全部生效。Codex 需要用户在 `/hooks` 亲自审阅信任，看板不能替用户写信任记录。合作者在自己的 Mac 启用时会生成自己的路径与备份，无需复制维护者配置。

执行计数可使用新鲜的明确 hook/event，即使进程绑定未知；明确离线不计入，超过 120 秒无新执行事件仍降为待确认。`Stop` 显示空闲，`SessionEnd` 显示运行结束；工具结束不能当作整个 Agent 空闲。采集优先读取状态传输，防止稍晚刷盘的原始记录抢先覆盖本轮状态；处理去重、已结束轮次与工具的迟到事件，且不采集任务正文。

桌面客户端可能在工作进程退出后复用同一会话；新一轮开始会清除旧的离线标记。无法绑定进程时保持 `liveness=unknown`，不能把收到事件直接显示成进程在线。

WorkBuddy 5.8.2 的安全沙箱审批不会总是触发 hook，因此自动补读 `logs/<日期>/sdk/conversations/*.log` 中的明确状态机转换。日志路径、标记、身份、信号和目标状态均验证；其余正文不进入存储。原始来源只读，不读取 IPC 凭据，不调用批准或执行接口。新任务日志每轮发现，原生状态能补充沙箱待批准和允许后的恢复；`PHASE_IDLE` 不当作本轮空闲，桌面会话有原生来源时不使用 CLI 工作进程的 SessionEnd 覆盖它。未知格式忽略，不能承诺未来客户端版本兼容。

WorkBuddy 上下文分母仍未知。豆包工作本次检查未找到可稳定读取桌面会话状态的公开接口，保持未接入；Claude Cowork 和普通 Chat 也未接入。桌面顶部灵动岛仍未实现。应用跳转按来源精度执行，打开应用不等于已定位原会话。

订阅卡片由独立 `GET /api/subscriptions` 提供，不受会话筛选影响。Codex 读取本地额度快照；Claude 需要状态栏实际报告；WorkBuddy 积分 API 已实现，但需要正式 OAuth 访问凭证，当前账号尚未验证。前端不得把“接口实现”显示为“当前账号已授权”，也不得把旧快照或已过重置时间的值标为实时剩余。详见 API 文档与 README 的配置说明。
