# 真实客户端状态与额度验收

本文用于人工验证真实客户端与 AgentWatch 的状态和额度是否一致。所有表格初始均为待验收，不代表当前机器、账号或客户端已经通过。演示模式和人工样例用于界面开发，不能作为本文的真实接入证据。

## 验收范围与证据边界

以下三项必须分别记录，不能相互替代：

| 层次 | 可以证明什么 | 不能证明什么 |
| --- | --- | --- |
| 配置齐全 | 看板所需的配置项已经存在 | 客户端已信任、配置已加载、实际事件已经触发 |
| 收到事件 | 至少有一个实际事件到达看板 | 所有事件均可用、完整交互链路正确、其他入口同样支持 |
| 端到端验收 | 指定客户端、版本和入口下，用户实际交互与看板状态对应 | 其他版本、入口、账号或尚未执行的场景已经通过 |

单元测试验证人工构造的输入和代码规则；浏览器验收验证页面行为。两者均不能替代真实客户端交互。Claude Code 的终端、VS Code 和桌面 Code 入口分别验收，不将其中一个入口的结果推广到其他入口。Claude Cowork、普通 Chat 等尚未接入的产品不纳入通过范围。

## 开始前

1. 使用已经运行的真实看板；先确认服务状态，避免另启实例占用相同端口。页面必须由 AgentWatch 自己的 Python 服务提供，并从同源首页进入。
2. 确认接口的 `demo` 为 `false`。演示页面、演示事件或手工注入的事件均不能用于真实客户端验收。
3. 只读查看接入设置和额度卡片，记录配置状态、最近上报时间、来源和是否陈旧。不要读取或展示凭据、任务正文、工具参数及客户端私有认证文件。
4. 优先使用无敏感内容、无外部副作用的人工验收任务。真实权限批准、问题回答和客户端信任审阅由用户亲自在原客户端完成。
5. 不修改客户端信任记录、批准策略或安全规则来制造通过结果。若现有策略没有产生真实批准框，记录为“未触发”，保留该项待验收。

读取接口需要同源首页 cookie；状态检查不需要修改配置。不要关闭 Origin、cookie 或 CSRF 校验。客户端配置文件保存成功后，仍需新开或继续客户端会话观察实际事件。

## Claude Code 配置检查

只读查看接入设置，或读取 `GET /api/integrations`：

- `claude.complete` 仅表示状态事件配置齐全。
- `claude.statusline_enabled` 仅表示看板状态栏配置已存在，不保证客户端已调用它。
- `last_hook_at` 仅表示最近收到 Claude 上报的时间，不能单独证明该上报属于本次验收的入口或事件类型。

配置未启用或不完整时，由用户从看板的“预览 Claude Code 接入”查看新增内容，再决定是否启用。需要额度时，先勾选“同时上报终端上下文和订阅额度”，再预览并启用；不要由开发 Agent 直接改写配置。已经启用时先检查实际上报，不重复安装。

若预览或保存提示配置已变化，保留当前设置，重新预览；若无法安全合并，记录受限原因，不覆盖其他配置。配置完成后，使用新启动的 Claude Code 会话继续验证。

## Claude Code 状态链路

每个实际使用的入口分别执行以下两条链路。验收时由用户在页面识别对应卡片；共享记录中只记入口、事件来源、状态变化和时间是否匹配，不写真实会话标识或任务内容。

### 执行 → 等待批准 → 继续执行 → 空闲

1. 用户在原客户端提交人工验收任务。观察卡片出现新鲜的执行状态；明确事件可确认执行，即使进程绑定仍未知，也不能因此将进程显示为在线。
2. 让客户端按原有策略触发一次真正的权限批准。用户先保留批准框，不立即处理。若没有出现批准框，该步骤未触发，不将普通提问卡片当作替代。
3. 在批准框仍存在时检查同一卡片：`state=waiting_approval`、`state_source=hook`，状态时间与本次操作对应，且没有陈旧提示。可对应 `PermissionRequest` 或权限通知事件。
4. 用户在原客户端亲自决定是否允许。只有实际允许后才验收继续执行；拒绝或取消应单独记录其实际结果，不推测任务已经完成。
5. 允许后检查新事件使卡片继续执行，回复结束后为 `idle`。工具返回只能说明工具阶段结束，不能提前视作整轮空闲。若过程太快而未观察到中间状态，记录该阶段缺少证据，不能补写通过。
6. 若用户结束整个客户端运行，单独检查 `ended`；它与本轮回复结束后的 `idle` 不同，均不代表业务目标成功。

### 执行 → 等待回复 → 继续执行 → 空闲

1. 用户在原客户端提交一个需要澄清的人工问题，并要求使用客户端实际的提问工具。普通文本中出现问号，不足以证明客户端正在等待交互。
2. 保留客户端的真实问题卡片，检查对应卡片为 `waiting_user`，来源为新鲜 hook，状态时间与交互对应。`AskUserQuestion` 对应等待回复；`ExitPlanMode` 可对应等待确认方案。
3. 用户在原客户端亲自回答或确认，再检查继续执行和最终 `idle`。页面不能代替用户提交回答或批准。
4. 若客户端没有触发提问工具或等待通知，记录“未触发”，不注入事件、不把推测状态当作验收结果。

## Claude Code 订阅额度

1. 只读确认 `claude.statusline_enabled`。未启用时，按上文由用户从界面勾选状态栏选项、预览并启用；不直接改写配置。
2. 用户在其 Pro/Max Claude Code 账号下，新启动会话并完成一次普通回复。额度来自客户端实际提供的状态栏字段，不能从会话 token 推算。
3. 读取 `GET /api/subscriptions`，检查 Claude 平台的窗口来源为 `claude_statusline`，`updated_at` 和窗口 `observed_at` 与本次报告对应。反复请求接口或点击更新，不应仅凭请求时间把旧来源时间刷新成当前时间。
4. 分别核验实际报告的 `five_hour` 和 `seven_day`；两种窗口允许独立缺失。未报告的窗口不补造为 0 已用或 100% 剩余；完全没有报告时记录为未知或未取得数据。
5. 在用户原客户端能看到对应窗口时，由用户对照窗口口径、重置时间和数字。无法找到同口径对照时，记录已收到报告及尚未完成的对照项，不宣称额度实时准确。
6. 记录来源时间和陈旧状态；账号切换后，旧快照不能作为新账号额度的证明。

## WorkBuddy 正式 OAuth 积分

本地会话和状态可读，不代表积分接口已授权。正式积分来自官方 `GET /openapi/v2/credit`，需要具有 `user.credit.readable` 权限的官方 OAuth access token；不使用桌面软件的私有认证数据。

1. 用户自行通过官方第三方应用授权流程取得正式凭证。开发 Agent 不索取、接收、读取、打印或保存 token，也不检查私有认证文件来补齐授权。
2. 用户若已具备正式凭证，按 README 的隐藏输入方式自行配置 `AGENTWATCH_WORKBUDDY_ACCESS_TOKEN`，并在该环境中启动真实服务。token 不放入命令参数、聊天、仓库或共享验收记录。当前项目未实现应用注册、OAuth 登录界面或自动续期。
3. 只读查看积分卡片或 `GET /api/subscriptions`。缺少凭证时不应发起积分请求；`auth_required` 也可能表示授权失败，不能仅据该状态断言具体原因。
4. 正式查询成功后，检查来源为 `workbuddy_openapi`，源时间更新，窗口单位为 `credits`。积分是有效资源包合计，不能标为周订阅额度，也不承诺能够拆分订阅、充值或赠送积分。
5. 由用户在官方渠道核对相同口径的总额、已用和剩余。没有同口径对照时保留该项待验收。总额为 0 时百分比应未知；不能除零。接口没有报告重置时间时保持未知。
6. “更新额度”只代表请求后台查询，不代表已经取得新值。最短查询间隔为 30 秒，常规后台周期为 5 分钟；以来源时间是否变化判断实际更新，不能用页面请求时间替代。
7. 不为制造失败而撤销授权或修改凭证。自然出现授权失败、超时或响应异常时，按下文核验错误与旧快照；其他失败分支使用人工样例测试，不将模拟结果写成当前账号实测。

| 检查项 | 结果 | 证据摘要或受限原因 |
| --- | --- | --- |
| 正式授权前提由用户确认 | 待验收 | 不记录凭证或账号信息 |

## 失败、未知与陈旧结果

- `null` 表示未知或没有取得数据；页面显示“—”或明确空态。未知不能改写为 0，缺窗不能补成 100% 剩余。
- 进程在线不能证明正在执行。超过 120 秒没有新执行事件的 active 应保守降为待确认；不能仅凭降级判断客户端已经停止。
- 旧等待状态可以保留，但必须展示陈旧提示。旧的等待记录不能证明当前仍有批准框或问题卡片。
- 额度超过 900 秒或来源时间异常时显示旧快照。已到重置时间的窗口，剩余量和剩余百分比为未知，直到来源重新报告；不能自行恢复为 100%。
- WorkBuddy 查询失败可以保留本进程此前取得的值，但必须标为旧值，并保留平台级错误或授权提示。错误不能变成零余额，也不能被旧数值掩盖。
- 接口不可达、读取被系统限制、配置不能安全合并或事件未触发时，记录具体受限层次。不要将“无法检查”写成服务停止、权限已拒绝或验收失败的确定结论。

## 共享验收结论

每项结果使用“待验收、未触发、通过、失败、受限”之一，并写明客户端版本、入口、验证范围和缺少的证据。共享记录仅保留允许的状态、来源、时间匹配结论和脱敏说明，不提交真实会话标识、文件路径、账号值、配置内容、凭据、正文或个人截图。

发现问题后，先保留用户当前配置和安全策略，再用人工构造样例补充回归。修复后的静态检查或单元测试通过，也要分别记录尚未重做的真实客户端步骤。
