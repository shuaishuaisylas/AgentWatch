## 3 用户已经确认的产品规则

常驻层无图标、单行，仅显示大于零的“执行”和“待处理”项。两项均无确认数量时自动隐去整个胶囊（含额度边缘），新鲜的执行或待处理出现后自动恢复；不显示连接中、待确认、零计数或状态待更新。自动隐去不写手动暂隐偏好，轮询仍为 4 秒；用户手动暂隐继续优先。背景必须真实透出后方窗口和壁纸，额度只在胶囊可见时用边缘细线表示；确认执行时仅在已用额度段内流动微光。不能因鼠标路过、轮询、待处理事件自动展开或抢焦点。

| 项目 | 当前规则 |
| --- | --- |
| 执行数 | 只统计确认执行的明确主会话，使用 `counts.active`；不加子 Agent，不把进程在线视为执行 |
| 人工待处理 | 需要用户实际回复、批准或操作，且未由用户核对后消除本地提醒的请求；同一根主会话多项只计 1，明确子树请求归到根 |
| 完成待查看 | 观察到可靠本轮完成、近 24 小时、尚未确认看过的主会话；“本轮结束”不等于业务目标验收成功 |
| 胶囊待处理数 | `inbox_counts.pending`，为人工待处理根与合格未读完成根的并集，在服务端截断前去重 |
| 状态独立 | 同一主会话可以同时执行和需要人工回复；自动批准、单纯错误不属于人工待处理 |
| 详情内容 | 仅三组紧凑会话列表，每条保留名称、平台、状态、相对时间；人工待处理优先，同一会话不重复 |
| 分组标题 | “待回复 / 待批准”“正在执行”“完成待查看”；仅删除操作提示文字，右键功能不变 |
| 名称 | 正式项目显示名优先；Codex 无正式项目时使用会话名（人工别名 → 侧栏标题），再以可读目录兜底；其他平台保留目录项目名优先。名称完整显示并自然换行，不另设字符显示上限，无鼠标悬停功能；内部项目 ID 不用于兜底，不从正文生成名称 |
| 滚动条 | 仅详情滚动或拖动期间显示，停止后自动隐藏，不改系统偏好、不预留常驻滚动槽 |
| 最近完成 | 独立完整候选中筛选合格未读结果后，最多显示 5 条；移除后下一条补位，因此可见条数未必减少 |
| 跳转 | 点击整张卡片，无独立跳转按钮；遵循 `jump.available/kind/precision` |

### 查看后何时移除

- **完成待查看**：准确跳转收到成功结果后，原生端再发送该完成版本的已读确认，卡片移除、数量减少。
- **非精确跳转**：仅打开应用、项目、原终端标签页不能证明看过指定结果，不自动已读。
- **手动已读**：右键完成卡片一次即确认对应完成版本已读，成功后立即移除并减数，不再出现二次按钮或系统菜单。
- **待回复 / 待批准**：普通左键跳转或查看不清除，收到匹配的实际处理信号仍按原路径移除。用户最新要求右键主卡一次即消除当前批次的本地提醒，成功后立即更新当前同版本的卡片与数字，再读取完整聚合。这不等于来源请求已解决，也不替用户回答或批准；新版本请求、执行与未知覆盖保留。
- **直接在原客户端查看**：当前没有稳定的已读信号，不能可靠自动识别；不使用应用前台、窗口焦点、文件修改时间或读取/恢复会话事件猜测已读。实际回复和审批有可靠信号时仍会同步。
- 新一轮完成是新版本，会再次出现；旧已读请求不能吞掉后来的完成。

## 4 实现入口和不可退回的技术约束

### 原生客户端

- `desktop/Sources/AgentWatchCapsule/main.swift`：应用生命周期、三组列表、轮询渲染、菜单栏、穿透及窗口观察者。
- `CapsulePanel.swift`：非激活面板、真实背景材质、额度描边/微光、点击和拖动。材质使用 `NSVisualEffectView.behindWindow`，alpha 遮罩只作用于材质，不能降低整个窗口 alpha 来替代。
- `DetailsPanel.swift`：`SessionRow` 是 `NSView`，左键导航、右键直接执行当前完成／人工提醒的版本动作，无二次按钮或系统菜单。无有效版本、纯执行卡及请求中不执行；复用卡片时重置旧闭包。名称完整多行显示，行高随内容增加、摘要独立排列；无名称跟踪区、计时器、浮层或系统 `toolTip`。`ActivityScrollView` 管理详情覆盖滚动条，只在滚动期间显示，不预留滚动槽。
- `ClientController.swift`：请求、跳转后再已读、手动已读、显式消除本地人工提醒、请求代次；写入成功后拒绝之前在途的旧快照，随后重新读取。POST 不自动重试。
- `desktop/Sources/CapsuleCore/`：`Models.swift`、`CapsuleState.swift`、`QuotaState.swift`、`Geometry.swift`、`APIClient.swift`，对应模型、完整计数/列表映射、额度、几何、安全传输。

状态和额度各 4 秒轮询，暂隐各 12 秒；同端点不积压请求。超时 6 秒，状态最后成功读取超过 15 秒后过期并停微光。额度独立核对来源时间、窗口状态和重置，不能拿本次 GET 时间冒充新报告。

### 后端及接口

完整字段以 [API 约定](API.md) 为准，以下是继续开发最容易混淆的部分：

- snapshot 显式请求 `role=main`；新增 `attention_counts`、卡片 `attention`、`last_completed_at`、独立 `recent_completed`、`inbox_counts` 和卡片 `inbox`。旧 Web 计数保持兼容，不能照搬旧 waiting/error 加法作为胶囊待处理。
- 名称来源见 `agentwatch/codex_names.py`：Codex 侧栏会话名优先只读 `session_index.jsonl` 的 `thread_name`，旧 SQLite `threads.title` 仅兼容回退，两者可能不同。内部 `session_title_source` 持久化来源，曾取得侧栏名后，缺失/损坏的索引不允许降级覆盖；该内部字段不出 API。
- 卡片兼容新增可空 `project_display_name`，来自客户端正式项目目录和身份；全局元数据 `local-projects` 与原生 SQLite `projects` / `project_roots` 按迁移身份和更新时间合并，优先显式线程身份，无身份时仅标准化完整根路径精确匹配；冲突/不兼容保留未知。原 `project_name` 和 `project_id` 继续用于既有工作目录聚合，不改写 Web 筛选或导航。名称规范空白与 NUL、最多 160 字，不覆盖人工别名，也不读取正文生成名称。
- `attention_counts.pending` 只含人工请求；`inbox_counts.pending` 才是当前胶囊总提醒。不能从截断卡片或可见 5 条完成卡反推全量。
- 主卡 `attention.dismiss_version` 为 64 位小写 SHA-256 字符串或 null，取完整明确、可见根子树中尚未解决且未手动消除本地提醒的 `waiting_user` / `waiting_approval` 请求批次；unknown 不参与。旧后端缺字段或无可消除批次时不显示入口。
- `POST /api/attention/dismiss` body 为 `{"id":"codex:demo-design","version":"当前 attention.dismiss_version"}`，复用 cookie/CSRF。缺少或隐藏会话、child／unknown 角色为 404，版本格式无效为 400，批次变化或已无该批请求为 409，成功为 `{"dismissed":true}`。独立 `attention_dismissals` 只存最少身份、`opened_at` 和 `dismissed_at`，绝不改 `interaction_requests.resolved_at`。旧回放不复活已消除的提醒，后续新请求仍提醒，旧确认不吞新请求，unknown 覆盖保留。
- `interaction_requests` / `interaction_aliases` 保存最少身份、类型、索引和时间；`attention_files` 独立版本/偏移回读历史元数据，不重置 usage 游标、不重算 token、不覆盖当前 hook 执行状态。首次回读可能较重；来源不完整保留 unknown。
- 异步提问识别当前 `questions[].title` 等已知格式，匹配 `accepted:true` 才确认已投递；accepted 不是用户回答。只有同会话、同调用、同索引的严格原生回复包装等可靠证据才能解决问题。普通消息、其他工具返回或开始新一轮不能清空未答请求。
- 单独的 `PermissionRequest` 发生在自动审核之前，不能当作人工待批准；需要明确面向用户且能关联的证据。自动允许/拒绝不能制造人工待处理。
- 只有可靠本轮结束事件写 `last_completed_at`；普通 idle、工具完成、进程退出、取消、中断和错误不生成成功完成提醒。完成候选还要求当前 idle/ended、无人工请求、无待处理覆盖未知。
- `POST /api/jump` **完全不写已读回执**。原生端仅在精度是“指定会话/会话路由”、返回 `opened=true` 且 kind 匹配时，再 POST `/api/inbox/read`。
- 已读 body 为 `{"id":"codex:demo-complete","completed_at":"1792029600"}`，以上是人工示例。`completion_receipts` 单调记录读到的完成时间，旧版本不清新版本；不会解决人工请求。
- 固定 loopback origin，独立内存 cookie/CSRF，拒绝重定向；GET 401 最多重新认证重试一次，POST 401、超时或结果不明均不自动重放。不要把已读合并进 jump，也不要为联调放宽校验。

订阅额度仍由 `/api/subscriptions` 独立提供，不能用会话 token 推算。归档、内部审核 Agent、unknown 角色和未知值规则继续遵守 `AGENTS.md`。

## 5 启动和安全重启

所有命令在仓库根目录执行。先核对目标服务身份，不抢占端口、不终止未知进程。

```sh
# 完整人工演示：拥有自己的临时服务，默认自动选空闲端口
./desktop/scripts/run-demo.sh

# 正常模式：先确认真实看板已运行；没有运行时使用原“启动看板.command”
./启动胶囊.command

# 已有正常构建、只需连接既有服务，不重新构建
python3 desktop/scripts/launch.py --real

# 其他固定本机端口
python3 desktop/scripts/launch.py --real --url http://127.0.0.1:8768

# 仅构建；先退出运行中的胶囊
./desktop/scripts/build.sh
```

**先从菜单栏“胶囊 → 退出胶囊”，再构建或切换服务。** 根目录启动脚本会先构建，不能覆盖正在运行的可执行文件。正常启动器只连接既有真实服务，退出胶囊不关闭它；演示只停止自己创建的临时服务和胶囊。Python 代码修改后须重启经核对属于本任务的服务，新会话不要照旧 PID 杀进程。

`build.sh` 现会拒绝在胶囊仍运行或无法确认进程状态时构建，包含演示/QA 胶囊；这项保护不会主动退出任何进程。

正常模式不带 `AGENTWATCH_CAPSULE_QA*`、`--material-probe` 或 `--expect-demo`。`AGENTWATCH_CAPSULE_QA_DETAILS=1` 仅为工具固定详情布局，会隐藏胶囊并暂停外部点击收起/部分显示变化收起；它不证明正常外部点击或穿透。材质 probe 修改产物标记，结束后须正常重建。

- 当前没有原客户端“只查看”的可靠已读事件，不承诺自动消除；已读提供显式右键补充。
